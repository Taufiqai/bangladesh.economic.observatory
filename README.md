# বাংলাদেশ অর্থনৈতিক পর্যবেক্ষণাগার: সুরক্ষিত ওয়েবসাইট

এই প্যাকেজ পর্যবেক্ষণাগারকে এমনভাবে প্রকাশ করে যে **কেবল তালিকাভুক্ত নির্দিষ্ট ব্যক্তিরাই** এটি দেখতে পান। প্রবেশের জন্য তিনটি জিনিস লাগে: অনুমোদিত তালিকায় থাকা ইমেইল, ব্যক্তিগত পাসওয়ার্ড এবং মোবাইলের অথেনটিকেটর অ্যাপের ৬ অঙ্কের কোড।

## কী কী সুরক্ষা আছে

| স্তর | কাজ |
| --- | --- |
| নামের তালিকা | কেবল `users.json`-এ থাকা সক্রিয় ইমেইল ঢুকতে পারে। তালিকা থেকে বাদ দিলে পরের ক্লিকেই প্রবেশ বন্ধ। |
| দ্বি-স্তর যাচাই | পাসওয়ার্ড (PBKDF2-SHA256, ২,১০,০০০ রাউন্ডে সংরক্ষিত) + অথেনটিকেটর কোড (TOTP)। একই কোড দুবার চলে না। |
| সেশন | HMAC-স্বাক্ষরিত কুকি (HttpOnly, Secure, `__Host-`), ডিফল্ট ৮ ঘণ্টা। `OBS_SESSION_EPOCH` বদলালে সবাই একসঙ্গে লগ-আউট। |
| লকআউট | একজনের ৫টি ভুল চেষ্টায় ১৫ মিনিট লক; একই নেটওয়ার্ক ঠিকানা থেকে ৩০টি ভুলে সেই ঠিকানা লক। |
| অডিট লগ | প্রতিটি সফল/ব্যর্থ লগইন, লগ-আউট ও পাতা দেখা: সময়, ইমেইল, আইপি, ব্রাউজার। অ্যাডমিন `/_auth/audit` পাতায় দেখতে পান (অন-প্রেম)। |
| ওয়াটারমার্ক | প্রতিটি পাতায় ব্যবহারকারীর নাম, ইমেইল ও সময় হালকা করে ছাপা থাকে; স্ক্রিনশট ফাঁস হলে উৎস চেনা যায়। |
| অদৃশ্যতা | `noindex`, `no-store`, `X-Frame-Options: DENY`: সার্চে আসে না, ক্যাশ হয় না, অন্য সাইটে এমবেড হয় না। |
| নেটওয়ার্ক সীমা (ঐচ্ছিক) | `OBS_ALLOWED_CIDRS` দিলে কেবল সরকারি নেটওয়ার্কের ঠিকানা থেকে খোলা যাবে। |
| ব্যর্থ হলে বন্ধ | গোপন কী সেট না থাকলে সাইট কাউকে ঢুকতে দেয় না (৫০৩)। |

পরীক্ষা: `npm test` চালালে ২৭টি নিরাপত্তা-পরীক্ষা চলে (ভুল পাসওয়ার্ড, ভুল কোড, কোড পুনর্ব্যবহার, জাল কুকি, মেয়াদোত্তীর্ণ সেশন, পাথ ট্রাভার্সাল, ওপেন রিডাইরেক্ট, লকআউট, তালিকা থেকে বাদ, পাসওয়ার্ড রিসেটে পুরোনো সেশন বাতিল, সবাইকে লগ-আউট, নেটওয়ার্ক সীমা ইত্যাদি)।

## ফোল্ডার

```
public/index.html     পর্যবেক্ষণাগার (দ্বিভাষিক, অফলাইন সংস্করণ)
auth/core.mjs         প্রবেশ-নিয়ন্ত্রণের মূল কোড
middleware.js         Vercel-এ চালানোর অ্যাডাপ্টার
server.mjs            সরকারি সার্ভারে (জাতীয় ডেটা সেন্টার) চালানোর অ্যাডাপ্টার
tools/users.mjs       ব্যবহারকারী যোগ/বাদ/রিসেট
test/e2e.mjs          স্বয়ংক্রিয় নিরাপত্তা-পরীক্ষা
```

## ব্যবহারকারী ব্যবস্থাপনা

```bash
npm install
node tools/users.mjs secret                                   # একবার: OBS_SESSION_SECRET তৈরি
node tools/users.mjs add jsecy@cabinet.gov.bd "নাম" viewer     # নতুন ব্যবহারকারী (admin বা viewer)
node tools/users.mjs reset jsecy@cabinet.gov.bd                # পাসওয়ার্ড বা ফোন হারালে
node tools/users.mjs disable jsecy@cabinet.gov.bd              # সাময়িক বন্ধ (enable দিয়ে চালু)
node tools/users.mjs remove jsecy@cabinet.gov.bd               # স্থায়ীভাবে বাদ
node tools/users.mjs list
```

`add` ও `reset` প্রতিজনের জন্য `handover/` ফোল্ডারে একটি **হস্তান্তর পাতা** তৈরি করে: প্রাথমিক পাসওয়ার্ড ও অথেনটিকেটরের QR কোড। পাতাটি মুদ্রণ করে সিলমোহরকৃত খামে দিন, তারপর ফাইলটি মুছে ফেলুন। কোনো পাসওয়ার্ড ইমেইল বা মেসেজে পাঠাবেন না।

`users.json`-এ পাসওয়ার্ড নয়, কেবল তার হ্যাশ থাকে; তবে অথেনটিকেটরের গোপন কী থাকে। তাই ফাইলটি গোপনীয় নথির মতো রাখুন এবং কখনো গিট রিপোজিটরিতে তুলবেন না (`.gitignore`-এ বাদ দেওয়া আছে)।

## বিকল্প ১: পাইলটের জন্য Vercel

1. গিটহাবে একটি **প্রাইভেট** রিপোজিটরিতে ফোল্ডারটি রাখুন (`users.json` ছাড়া)।
2. ব্যবহারকারী যোগ করে চালান: `node tools/users.mjs export` → যে লম্বা লাইন আসে, সেটিই `OBS_USERS`।
3. Vercel প্রকল্পের Settings → Environment Variables-এ দিন:
   - `OBS_SESSION_SECRET` = `secret` কমান্ডের ফল
   - `OBS_USERS` = `export` কমান্ডের ফল
   - `OBS_SESSION_EPOCH` = `1`
   - ঐচ্ছিক: `OBS_SESSION_HOURS` (ডিফল্ট ৮), `OBS_ALLOWED_CIDRS` (যেমন `103.48.16.0/22`)
4. ডিপ্লয় করুন। প্রতিটি অনুরোধ আগে `middleware.js` দিয়ে যায়, তাই লগইন ছাড়া কোনো ফাইলই দেখা যায় না।

Vercel-এ লক্ষণীয়: ব্যবহারকারী বদলালে `export` আবার চালিয়ে `OBS_USERS` হালনাগাদ করে **পুনরায় ডিপ্লয়** করতে হয়। লকআউট-গণনা প্রতিটি সার্ভার-ইনস্ট্যান্সে আলাদা থাকে; বাড়তি সুরক্ষার জন্য Vercel Firewall-এ `/_auth/login`-এর ওপর একটি রেট-লিমিট নিয়ম যোগ করুন। অডিট লগ দেখা যায় Vercel → Project → Logs-এ।

## বিকল্প ২: পূর্ণ বাস্তবায়নে সরকারি সার্ভার (জাতীয় ডেটা সেন্টার)

তথ্য দেশের ভেতরে রাখতে এটিই সুপারিশকৃত পথ। Node.js ২০ বা তার পরের সংস্করণ লাগে।

```bash
# /etc/obs.env  (chmod 600)
OBS_SESSION_SECRET=...
OBS_SESSION_EPOCH=1
OBS_USERS_FILE=/srv/obs/users.json
OBS_AUDIT_FILE=/var/log/obs/audit.log
OBS_TRUST_PROXY=1
HOST=127.0.0.1
PORT=8080
# OBS_ALLOWED_CIDRS=10.0.0.0/8
```

systemd ইউনিট (`/etc/systemd/system/obs.service`):

```ini
[Service]
EnvironmentFile=/etc/obs.env
WorkingDirectory=/srv/obs
ExecStart=/usr/bin/node server.mjs
User=obs
Restart=always
```

nginx (TLS সহ):

```nginx
server {
  listen 443 ssl http2;
  server_name observatory.cabinet.gov.bd;
  ssl_certificate     /etc/ssl/obs/fullchain.pem;
  ssl_certificate_key /etc/ssl/obs/privkey.pem;
  location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header X-Forwarded-Proto https;
  }
}
```

এখানে `users.json` বদলালেই কাজ হয়, পুনরায় চালু করতে হয় না; কাউকে বাদ দিলে তাঁর পরের ক্লিকেই প্রবেশ বন্ধ। অ্যাডমিনরা `/_auth/audit` পাতায় সর্বশেষ ৩০০টি ঘটনা দেখতে পান।

## জরুরি পরিস্থিতিতে

| পরিস্থিতি | করণীয় |
| --- | --- |
| একজনের পাসওয়ার্ড বা ফোন হারিয়েছে | `reset` চালান; পুরোনো পাসওয়ার্ড ও কোড সঙ্গে সঙ্গে অকেজো |
| কেউ বদলি বা অবসরে গেছেন | `remove` চালান (Vercel হলে `export` ও পুনরায় ডিপ্লয়) |
| তথ্য ফাঁসের সন্দেহ | `OBS_SESSION_EPOCH` এক বাড়ান: সবাই লগ-আউট; অডিট লগ ও ওয়াটারমার্ক দেখে উৎস খুঁজুন |
| গোপন কী ফাঁস | নতুন `secret` তৈরি করে `OBS_SESSION_SECRET` বদলান (সবাই লগ-আউট হবেন) |

## সীমাবদ্ধতা

- ওয়াটারমার্ক স্ক্রিনশট আটকায় না; এটি উৎস শনাক্ত করে ও নিরুৎসাহিত করে।
- ব্যবহারকারী নিজে পাসওয়ার্ড বদলাতে পারেন না; প্রশাসক `reset` দিয়ে নতুন পাসওয়ার্ড দেন।
- `public/index.html` একটি নির্দিষ্ট তারিখের তথ্য ধারণ করে। মাসিক স্বয়ংক্রিয় হালনাগাদ claude.ai-এর ড্যাশবোর্ডে হয়; এই সাইটে নতুন তথ্য আনতে হালনাগাদ `index.html` প্রতিস্থাপন করতে হবে।
- ব্যবস্থাটি ব্যবহারের আগে বিজিডি ই-গভ সিআইআরটির মাধ্যমে স্বাধীন নিরাপত্তা নিরীক্ষা করানো উচিত।
